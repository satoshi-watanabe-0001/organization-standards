# AI思考プロセス詳細ガイド・評価基準

本ファイルはセクション3（詳細説明）とセクション4（評価基準）、セクション5（実装ガイドライン）を統合したものです。

## パート1: 各セクションの詳細説明（3.1-3.9）

### 3.1 メタ情報

作業の基本情報を記録し、トレーサビリティを確保する。

**記載項目**:
- 作業の一意識別
- 時間管理情報
- 責任の明確化
- **推論深度レベル(1-5)**: AIがどの程度深く推論したかを自己評価

**推論深度の判断基準**:
- **Level 1**: 単純な結論のみ
- **Level 2**: 1段階の推論
- **Level 3**: 2-3段階の推論(標準)
- **Level 4**: 3-4段階の詳細な推論
- **Level 5**: 5段階以上の体系的推論

### 3.2 要件理解・解釈 ★推論の核心セクション

与えられた要件に対するAIの理解度と解釈を**推論プロセス付きで**明記する。

**重要ポイント**:
- **多段階推論の記録**: 要件から理解に至るまでの思考ステップを3段階以上記載
- **確信度の明示**: 各推論ステップに確信度(0-100%)を付記
- **仮定事項の推論根拠**: なぜその仮定を置いたのかを4段階で説明
  1. 観察事実
  2. 類似事例
  3. 論理展開
  4. 結論
- **不明点の構造的整理**: 影響度、推論で補えるか、確認必須度を評価

**推論品質チェックリスト**:
- [ ] 要件解釈に3段階以上の推論があるか
- [ ] 各推論に確信度が記載されているか
- [ ] 仮定事項に推論プロセスがあるか
- [ ] 推論の根拠が具体的か

### 3.3 作業分割・計画 ★推論による最適化

複雑な作業をどのように分割し、実行計画を立てたかを**推論根拠と共に**記述する。

**評価観点**:
- **分割戦略の選択推論**: なぜその分割方法を選んだのか(複数案を比較検討)
- **粒度決定の推論**: なぜその粒度にしたのかの判断根拠
- **依存関係の推論**: なぜ依存するのか、並列化できるのかの論理的説明
- **実行順序の最適化推論**: 初期順序→並列化検討→リスク駆動調整→最終決定の流れ

**推論品質チェックリスト**:
- [ ] 分割戦略選択に多段階推論があるか
- [ ] 依存関係の推論根拠が明確か
- [ ] 実行順序の最適化プロセスが記載されているか
- [ ] 確信度が適切に評価されているか

### 3.4 情報収集・参照 ★推論による情報選択

作業に必要な情報をどのように収集・活用したかを**選択理由の推論と共に**記録する。

**記載内容**:
- **情報探索戦略の推論**:
  - 何が不足しているか(知識ギャップ)
  - 何から調べるべきか(優先順位)
  - どうやって見つけるか(探索戦略)
- **リソース選択の推論**: なぜそのリソースを選んだのか
- **パターン適用の推論**: 適用可能性を4段階で評価
  1. パターンの特性
  2. 現状況との照合
  3. 適用条件の確認
  4. 適用判断
- **外部情報の妥当性評価**: 信頼性、最新性、適用可能性の推論

**推論品質チェックリスト**:
- [ ] 情報探索戦略に推論があるか
- [ ] リソース選択理由が明確か
- [ ] パターン適用可能性の推論が詳細か
- [ ] 適合度スコアが記載されているか

### 3.5 意思決定プロセス ★最重要推論セクション

複数の選択肢から最適解を選択する過程を**推論チェーン付きで**詳細に記述する。

**必須要素**:
- **選択肢の網羅的列挙**: 3個以上の選択肢を検討
- **各選択肢の推論分析**:
  - メリット分析(なぜメリットか+スコア)
  - デメリット分析(なぜデメリットか+スコア)
  - 実現可能性(なぜ可能/不可能か+スコア)
- **評価基準の重み付け推論**: なぜその重要度にしたのか
- **定量的スコアリング**: 数値による客観的評価
- **推論チェーンの可視化**: 前提→観察→推論→結論の流れ図
- **却下理由の推論**: 表面的理由と深層的推論を分離

**推論品質チェックリスト**:
- [ ] 3個以上の選択肢が検討されているか
- [ ] 各選択肢に推論とスコアがあるか
- [ ] 評価基準の重み付けに推論があるか
- [ ] 推論チェーンが可視化されているか
- [ ] 却下理由に深層的推論があるか
- [ ] 最終決定の確信度が記載されているか

### 3.6 リスク評価 ★推論によるリスク発見

作業に伴うリスクの識別と評価結果を**発見の推論プロセス付きで**記録する。

**リスクカテゴリ例**:
- 技術的リスク
- 性能・品質リスク
- セキュリティリスク
- 運用・保守リスク
- 期間・予算リスク
- 業務リスク

**推論の記載内容**:
- **リスク発見の推論**:
  1. きっかけ(何から気づいたか)
  2. 推論展開(どう考えたか)
  3. 影響範囲の推定(どこまで影響するか)
- **発生確率の推論**:
  1. 類似事例の分析
  2. 現状の脆弱性評価
  3. 予防措置の効果
  4. 最終確率の判断+根拠
- **影響度の推論**:
  1. 直接的影響
  2. 間接的影響(波及効果)
  3. 定量的影響の推定
  4. 最終影響度の判断
- **対策選択の推論**:
  - 複数対策案の発案理由
  - 費用対効果分析
  - 実現可能性評価
  - 最終選択の推論

**推論品質チェックリスト**:
- [ ] リスク発見の推論プロセスがあるか
- [ ] 発生確率の推論が多段階か
- [ ] 影響度の推論が詳細か
- [ ] 対策選択に推論があるか
- [ ] 確信度が適切に評価されているか

### 3.7 実行過程

実際の作業実行における判断や修正を時系列で記録する。

**記載内容**:
- 実行手順の詳細
- 途中での判断・修正とその推論
- 発生した問題と対処の推論

### 3.8 成果物・結果

作成した成果物とその品質評価を記述する。

**記載内容**:
- 成果物のリスト
- 品質確認結果
- 成果物の妥当性評価

### 3.9 振り返り・学習 ★メタ認知推論

作業を通じて得られた知見と今後の改善点を**原因分析の推論と共に**整理する。

**記載内容**:
- **うまくいった点**: 成功要因の推論分析
- **改善すべき点**:
  - 問題点の特定
  - 原因推論(なぜそうなったか)
  - 改善案の推論(どう改善するか)
  - 期待効果
- **今後の活用可能な知見**: 汎用化・再現性の推論

**推論品質チェックリスト**:
- [ ] 成功・失敗の原因分析に推論があるか
- [ ] 改善策の推論根拠が明確か
- [ ] 再現性・汎用化の推論があるか

## パート2: 評価基準（4.1-4.4）

### 4.1 思考プロセスの評価軸

#### 4.1.1 完全性(Completeness)
- [ ] 全ての必須セクションが記載されている
- [ ] 要件理解に漏れがない
- [ ] リスクが網羅的に識別されている

#### 4.1.2 論理性(Logic)
- [ ] 意思決定の根拠が明確である
- [ ] 作業分割が論理的である
- [ ] 実行順序に妥当性がある
- [ ] **推論の各ステップが論理的につながっている**
- [ ] **推論の飛躍がない、または飛躍の理由が説明されている**

#### 4.1.3 透明性(Transparency)
- [ ] 判断過程が追跡可能である
- [ ] 参照情報が明確に示されている
- [ ] 仮定事項が明記されている
- [ ] **推論の根拠が明確に示されている**
- [ ] **確信度や確率が数値で示されている**

#### 4.1.4 実用性(Practicality)
- [ ] 実装可能な計画である
- [ ] 制約条件が適切に考慮されている
- [ ] リスク対策が具体的である

#### 4.1.5 推論深度(Reasoning Depth) ★新規追加
- [ ] **要件から結論まで多段階の推論が記録されている**
- [ ] **Why(なぜ)が3回以上深掘りされている**
- [ ] **代替案の検討プロセスが詳細である**
- [ ] **推論の確信度が適切に評価されている**

### 4.2 定量的評価指標

| 指標 | 評価方法 | 目標値 | 測定箇所 |
|------|----------|--------|----------|
| 記載完全性 | 必須項目記載率 | 100% | 全セクション |
| 要件理解度 | 要件カバレッジ | 95%以上 | セクション1 |
| リスク識別率 | 重要リスクの発見率 | 90%以上 | セクション5 |
| 意思決定品質 | 選択肢検討数 | 3個以上 | セクション4 |
| **推論ステップ数** | **各推論の段階数** | **3段階以上** | **全セクション** |
| **推論確信度記載率** | **確信度の明記率** | **100%** | **主要判断箇所** |
| **根拠明示率** | **判断に根拠がある割合** | **100%** | **全判断箇所** |

### 4.3 推論品質スコアリング方式

各セクションの推論品質を5段階で評価:

**レベル1(不十分)**:
- 結論のみで推論過程が不明
- 根拠が示されていない
- 確信度の評価がない

**レベル2(最低限)**:
- 1段階の推論のみ
- 根拠が曖昧
- 確信度が一部のみ

**レベル3(標準)**:
- 2-3段階の推論
- 根拠が明示されている
- 確信度が主要箇所で示されている

**レベル4(良好)**:
- 3-4段階の詳細な推論
- 根拠が具体的で検証可能
- 確信度が全箇所で適切に評価
- 代替推論の検討がある

**レベル5(卓越)**:
- 5段階以上の体系的推論
- 根拠が多角的で論理的
- 確信度が定量的に評価
- 複数の推論パスの比較
- メタ認知的な推論の振り返り

**目標値**:

## パート3: 実装ガイドライン（5.1-5.2）

### 5.1 マイルストーン可視化の実践 ★最優先事項

#### 5.1.1 可視化タイミングの基本方針

本フレームワークでは、**マイルストーン可視化方式**を推奨する。これはPBI(Product Backlog Item)単位で作業を管理し、各作業の完了時点で思考プロセスを記録する方式である。

**マイルストーン可視化の利点**:
- ✅ 実務との親和性が高い(アジャイル開発と整合)
- ✅ 思考の進化が時系列で追跡可能
- ✅ 作業単位でレビューしやすい
- ✅ 適切な粒度(リアルタイム:細かすぎ、事後:不正確、マイルストーン:最適)

#### 5.1.2 記録タイミングの定義

**タイミング1: PBI開始時**
- **実施内容**: PBIマスターレポート作成
- **記録事項**: PBI全体の理解、作業分割計画、想定リスクの初期評価
- **所要時間**: 30-60分

**タイミング2: 各作業完了時** ⭐最も重要
- **実施内容**: 作業単位の思考プロセスレポート作成
- **記録事項**: その作業での要件理解・推論、意思決定プロセス、発見した課題・リスク、次作業への引き継ぎ事項
- **所要時間**: 45-75分

**タイミング3: 重要な意思決定時(緊急記録)**
- **実施内容**: 思考修正ログ作成
- **記録タイミング**: 前作業の判断を覆す必要が生じた時、新たな重大リスクを発見した時
- **所要時間**: 15-30分

**タイミング4: PBI完了時**
- **実施内容**: PBIマスターレポート完成
- **記録事項**: PBI全体の思考の流れ総括、思考品質の自己評価、学習した知見
- **所要時間**: 30-45分

### 5.2 作業間の思考連携機構 ★最優先事項

マイルストーン可視化では、各作業の思考プロセスファイルが独立して作成されるが、**作業間での思考の連続性**を保つことが極めて重要である。

#### 5.2.1 思考連携の必要性

**問題**: 作業ファイルが独立していると発生する課題
- 前作業の結論が次作業で無視される
- 前作業の仮定が検証されずに放置される
- 思考の矛盾が発見されない

**解決**: 思考リンクメカニズムの導入

#### 5.2.2 思考連携の実装方法

各作業の思考プロセスレポートに以下のセクションを**必須**で追加する:

**セクション0: 前作業からの思考継承**

```markdown
## 0. 前作業からの思考継承

### 0.1 前作業の重要な結論
| 継承ID | 前作業での結論 | 本作業での前提 | 変更有無 | 備考 |
|--------|--------------|--------------|---------|------|
| INH-001 | Stripe決済を採用 | Stripe APIを使用 | ✅変更なし | - |

### 0.2 前作業の仮定事項の検証
**前作業での仮定1**: クレジットカード決済のみで十分
- **本作業での検証結果**: 
  - 検証方法: ステークホルダーヒアリング実施
  - 結果: ❌仮定が不正確
  - 新事実: コンビニ決済も必要との要望
  - **思考の修正**: 決済手段を拡張(クレカ + コンビニ)
  - 影響範囲: API設計、決済フロー、テスト計画
  - **確信度**: 95%

### 0.3 前作業との整合性チェック
- [ ] 前作業で決定した技術選定が変更されていないか
- [ ] 前作業で設定した制約条件が守られているか
- [ ] 前作業で識別したリスクへの対策が計画されているか
```

**セクション9: 次作業への引き継ぎ**

```markdown
## 9. 次作業への引き継ぎ

### 9.1 次作業への前提条件
| 引継ID | 本作業の結論 | 次作業での前提 | 注意事項 | 優先度 |
|--------|------------|--------------|---------|-------|
| HAN-001 | 決済手段2種類に拡張 | Stripe + Konbini統合 | コンビニは非同期処理 | High |

### 9.2 次作業で検証すべき仮定
**仮定1**: Konbini Paymentsの決済完了通知は24時間以内
- **検証方法**: Stripe公式ドキュメント確認 + サポート問い合わせ
- **検証の重要度**: High
```
