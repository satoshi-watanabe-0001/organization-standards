# 🚀 Devin タスク実行チェックリスト（必読）

## このドキュメントの使い方

**すべてのタスク開始時に必ず確認する簡易チェックリスト**です。推論記録なしの作業は完了とみなされません。

---

## 📋 タスク開始前チェックリスト

### ✅ 準備確認（必須）

- [ ] **作業タイプを特定**（要件定義/設計/実装/テスト/デバッグ等）
- [ ] **推論テンプレートを準備**（下記の簡易版をコピー）
- [ ] **作業時間の10-15%を思考記録に割り当て**（例：6時間作業なら45-60分）
- [ ] **確信度評価の準備**（0-100%で数値化する準備）
- [ ] **選択肢検討の準備**（意思決定時は3つ以上の案を比較）
- [ ] **前作業の継承事項を確認**（依存する前提・仮定・結論があるか）
- [ ] **完了後チェックリスト目標を確認**（推論品質スコア70点以上）

---

## 🔄 タスク実行中チェックリスト

### ✅ 継続実施項目（必須）

- [ ] **判断の都度、推論を3段階以上で記録**
  - なぜ？（1段階目）→ なぜそう考えた？（2段階目）→ なぜその根拠？（3段階目）
- [ ] **確信度を必ず数値化**（「たぶん」「おそらく」は禁止）
- [ ] **選択肢は必ず3つ以上検討**（A案、B案、C案の比較）
- [ ] **仮定事項は必ず根拠を明記**（なぜその仮定を置いたのか）
- [ ] **参照した情報源を記録**（URL、ドキュメント名、選択理由）
- [ ] **リスクを発見したら即座に記録**（発見の経緯、影響度、対策）
- [ ] **中間判断のメモを随時追記**（作業完了後にまとめるのは非効率）
- [ ] **迷った時点で詳細版ガイドラインを参照**
- [ ] **前作業の仮定が正しいかを検証**（継承事項の妥当性確認）

---

## 📝 タスク完了後チェックリスト

### ✅ 品質確認（必須）

- [ ] **推論深度レベルを自己評価**（Level 1-5、目標はLevel 3以上）
- [ ] **推論品質スコアを算出**（目標70点以上）
- [ ] **確信度記載率100%を確認**（主要判断で数値記載漏れなし）
- [ ] **必須項目サマリーで最終チェック**（下記の表を使用）
- [ ] **次作業への引き継ぎ事項を明記**（前提条件、検証すべき仮定等）
- [ ] **学習ポイントを3つ以上記録**（うまくいった点、改善点、今後の活用）

## 🛠️ 推論記載テンプレート（簡易版）

### コピペして使用してください

```markdown
## 判断事項：[何を決めたか]

### 推論プロセス：
**ステップ1（観察）**：[何を見た/読んだか]
**ステップ2（分析）**：[どう分析したか] 
**ステップ3（結論）**：[なぜその結論に至ったか]

### 選択肢比較：
| 選択肢 | メリット | デメリット | スコア |
|--------|---------|-----------|-------|
| A案 | [利点] | [欠点] | X/10点 |
| B案 | [利点] | [欠点] | Y/10点 |
| C案 | [利点] | [欠点] | Z/10点 |

### 最終決定：
- **選択**：[A/B/C]案
- **決定理由**：[なぜその案を選んだか]
- **確信度**：[0-100%]

### リスク評価：
- **識別したリスク**：[リスク内容]
- **発生確率**：[高/中/低] - [推論根拠]
- **影響度**：[大/中/小] - [推論根拠]
- **対策**：[具体的な対策]
```

## ❌ よくある間違いと修正方法

### 🚫 間違い1：推論なしの結論
**NG例**：「React を使用する」
**OK例**：
```
判断：React を使用
推論：
1. 要件分析：SPA必要、高速レンダリング要求
2. 技術比較：Vue.js vs React vs Angular
3. 結論：学習コスト（React経験あり）と開発速度でReact最適
確信度：85%
```

### 🚫 間違い2：確信度が曖昧
**NG例**：「たぶん正しい」「おそらく動く」
**OK例**：「確信度75%」「検証後90%に向上」

### 🚫 間違い3：選択肢が1つのみ
**NG例**：「PostgreSQLを使用」（他の選択肢の検討なし）
**OK例**：「PostgreSQL vs MySQL vs MongoDB を比較。PostgreSQLが最適（ACID特性重視のため）」

### 🚫 間違い4：根拠のない仮定
**NG例**：「ユーザー数は1万人程度」
**OK例**：
```
仮定：ユーザー数1万人
根拠：
1. 観察：要件に「小規模サービス」
2. 類似例：過去案件平均8千-1.5万人
3. 推論：中央値として1万人想定
確信度：70%（ヒアリングで要検証）
```

### 🚫 間違い5：チェックリスト未実施
**NG例**：作業完了後、いきなり次のタスクへ
**OK例**：本チェックリストで品質確認→推論品質スコア算出→次タスクへ
