**ファイル名**: `AI-DOCUMENT-MODIFICATION-POLICY.md`

**目的**: AIによる組織標準ドキュメントの修正に関する厳格なルールを定義

#### 主要な内容

**🚨 最重要ルール**:
```yaml
絶対禁止:
  AIによる組織標準ドキュメントの直接修正は絶対に禁止

理由:
  - 組織全体に影響する
  - 複数プロジェクトに影響する
  - 品質保証プロセスが必要
  - 人間のレビュー・承認が必須

正しい手順:
  1. 問題を発見
  2. 課題起票（AI-ISSUE-TRACKING-PROCESS.mdに従う）
  3. 人間がレビュー・承認
  4. 人間が修正実施
```

**組織標準ドキュメントの定義**:
- `/organization-standards/` 配下の全ドキュメント
- 00-guides/、01-coding-standards/、02-architecture-standards/ 等の全ディレクトリ
- README.md、その他全ての .md ファイル

**絶対禁止事項**:
```yaml
❌ AIが絶対にやってはいけないこと:
  1. 組織標準ドキュメントの直接修正
     - タイポ・誤字の修正も禁止
     - 軽微な表記揺れの修正も禁止
     - 例の追加も禁止
     - リンク切れの修正も禁止
     - フォーマット調整も禁止
  
  2. 組織標準ドキュメントの削除
  3. 組織標準ドキュメントの新規作成
  4. 組織標準ドキュメントの移動・リネーム
```

**正しいプロセス**:
```yaml
ステップ1: 問題の発見
ステップ2: 課題起票（AI-ISSUE-TRACKING-PROCESS.md に従う）
ステップ3: 具体的な修正案を提案（diffスタイル）
ステップ4: 作業を継続（人間の修正を待つ必要はない）
ステップ5: 報告（優先度に応じた頻度）
```

**例外（修正可能なドキュメント）**:
```yaml
✅ AIが修正可能:
  - 個別PBI専用ドキュメント（docs/requirements/PROJ-1234-*.md等）
  - AIの判断記録ファイル（docs/ai-decisions/）
  - AI課題管理ファイル（docs/ai-issues/）
  - プロジェクト固有のドキュメント（/organization-standards/ 配下でない）

判断基準:
  ファイルパスに /organization-standards/ が含まれるか？
  Yes → ❌ 絶対に修正禁止、課題起票
  No → ✅ 修正可能（ただし慎重に）
```

## 🎯 このルールの重要性

### なぜこのルールが必要か

```yaml
組織標準ドキュメントの特性:
  - 組織全体で共通使用
  - 複数プロジェクトに影響
  - 厳格な品質管理が必要
  - 変更には人間の承認が必須

AIによる直接修正のリスク:
  - 意図しない影響が組織全体に波及
  - 複数プロジェクトで不整合が発生
  - 品質保証プロセスのバイパス
  - 変更履歴・承認記録の欠落
  - ガバナンスの崩壊
```

---

### 正しいプロセスの利点

```yaml
課題起票→人間が修正のメリット:
  1. 品質保証:
     - 人間のレビュー・承認を経る
     - 複数の視点でチェック
     - 影響範囲の適切な評価
  
  2. ガバナンス:
     - 変更履歴が明確
     - 承認記録が残る
     - トレーサビリティ確保
  
  3. 組織学習:
     - AIが発見した問題が蓄積
     - 傾向分析が可能
     - 継続的改善に繋がる
  
  4. リスク管理:
     - 不適切な変更を防止
     - 影響の大きい変更を慎重に実施
     - ロールバックが容易
```

## 🔍 具体例

### ❌ 禁止例: AIがやってはいけないこと

**例1: タイポ修正**
```markdown
phase-3-implementation-guide.md に以下のタイポを発見:
  "テストカバレッヂ" → "テストカバレッジ"

❌ AIがやってはいけないこと:
  - ファイルを直接修正する
  - git commit を作成する
  - PRを作成する

✅ AIがやるべきこと:
  - 課題を起票（AI-ISSUE-TRACKING-PROCESS.mdに従う）
  - 優先度: Low
  - カテゴリ: ドキュメント
  - diff形式で修正案を提案
  - 人間の修正を待つ
```

**例2: リンク切れ修正**
```markdown
README.md に以下のリンク切れを発見:
  [Phase 3ガイド](phase-3-guide.md) 
  → 実際のファイル名は phase-3-implementation-guide.md

❌ AIがやってはいけないこと:
  - README.md を直接修正する

✅ AIがやるべきこと:
  - 課題を起票
  - 優先度: Medium
  - カテゴリ: ドキュメント
  - 正しいリンクを提案
```

**例3: 情報の追加**
```markdown
testing-strategy.md に情報が不足していることを発見:
  "ユニットテストの目標カバレッジ: 80%以上"
  → "ビジネスロジック: 90%以上"の記載がない

❌ AIがやってはいけないこと:
  - testing-strategy.md に情報を追加する

✅ AIがやるべきこと:
  - 課題を起票
  - 優先度: High（作業に影響）
  - カテゴリ: ドキュメント
  - 追加すべき情報を具体的に提案（diff形式）
```
