## 移行概要

5つの改善により、以下を実現します：

1. **プロセスの理解向上** - Phase 2A/2B で実行順序が明確に
2. **AI作業制限の明確化** - 禁止事項の判定基準が具体化
3. **テンプレート発見性向上** - 42種類のテンプレートを即時発見

### 2. AI禁止事項の具体化

**新規ドキュメント**: [`01-coding-standards/ai-task-prohibitions-examples.md`](01-coding-standards/ai-task-prohibitions-examples.md)

#### 主要な禁止事項（10カテゴリ）

1. **マルチタスク禁止** - 複数PBIの同時作業は禁止
2. **ドキュメント生成禁止** - コード実装とドキュメント生成の混在禁止
3. **大規模リファクタリング禁止** - 500行以上の変更は分割必須
4. **外部依存追加の制限** - 新規ライブラリ追加は事前承認必須
5. **セキュリティ関連作業の制限** - 認証・認可は人間レビュー必須

#### OK/NG判定の使い方

ドキュメント内の**OK/NG判定マトリックス**と**判断フローチャート**を参照：

```
作業内容を確認
    ↓
該当カテゴリを特定
    ↓
具体例と照合
    ↓
OK/NG判定マトリックスで確認
    ↓
グレーゾーン？ → フローチャートで判断
```

### AI Devin

#### やるべきこと

**即時対応**
- [ ] Phase番号の理解: Phase 2A/2B と実行順序
- [ ] AI禁止事項ガイドの参照: 作業前に必ず確認
- [ ] テンプレートインデックスの活用: 必要なテンプレートを即時発見

#### 実行時の確認事項

**Phase実行前**:
```
1. 現在のPhaseを確認
2. Phase 2の場合:
   - Phase 2A（事前設計）: 実装前？ → OK
   - Phase 2B（事後文書化）: 実装後？ → OK
3. AI禁止事項ガイドで作業範囲を確認
4. テンプレートインデックスで必要なテンプレートを取得
```

**作業中**:
```
1. 単一PBIに集中（マルチタスク禁止）
2. コード実装のみ（ドキュメント生成混在禁止）
3. 500行以下の変更（大規模リファクタリング禁止）
```

#### 注意点

- **Phase 2B警告**: ⚠️このフェーズは実装後に実行
- **禁止事項**: グレーゾーンは判断フローチャート参照
- **テンプレート**: フェーズに応じたテンプレートを使用

## FAQ

### Q1: Phase 2A/2.2 を使い続けてもいいですか？

**A**: 移行期間中（2025-11-19〜2026-02-19）は可能ですが、新表記（Phase 2A/2B）への移行を推奨します。2026-02-20以降は新表記のみになります。

---

### Q2: Phase 2Bをいつ実行すればいいですか？

**A**: **Phase 4（レビュー・QA）の後**に実行してください。実行順序は以下の通りです：

```
Phase 2A（事前設計）
  ↓
Phase 3（実装）
  ↓
Phase 4（レビュー・QA）
  ↓
Phase 2B（事後文書化）← ここで実行
```

---

### Q3: AI禁止事項のグレーゾーンはどう判断しますか？

**A**: [`ai-task-prohibitions-examples.md`](01-coding-standards/ai-task-prohibitions-examples.md) の「判断フローチャート」を使用してください。それでも不明な場合は、人間にエスカレーションしてください。

---

### Q4: テンプレートが多すぎて覚えられません

**A**: 覚える必要はありません。[`TEMPLATE-INDEX.md`](08-templates/TEMPLATE-INDEX.md) を開き、フェーズ別セクションまたはクイックリファレンステーブルから必要なテンプレートを検索してください。

---

### Q5: プロセスパターンAとBの使い分けは？

**A**: [`process-pattern-selection-guide.md`](03-development-process/process-pattern-selection-guide.md) の選択フローチャートを使用してください。一般的には：

- **パターンA**: アジャイル、AI活用度が高い
- **パターンB**: ウォーターフォール、文書重視
- **パターンC**: スパイク、探索的開発

---

### Q6: Phase 2A で作成した設計書は Phase 2B で書き直しますか？

**A**: いいえ、書き直しではなく**進化**させます。Phase 2A の概要レベル設計に、実装で得られた詳細を追加してください。バージョン番号も v0.x → v1.0 に更新します。

---
